# 模块二关键 AI 对话记录

## 1 风险分析

**人工输入**

> 请审查 EgoBlind 的 `eval.py`。模块一已经覆盖评分边界和不安全 `eval`，请优先寻找普通单次单元测试难以覆盖的状态、缓存、文件系统和重复执行问题，并说明可复现方式。

**AI 输出摘要**

AI 指出评估目录按预测文件名复用。程序以“同名 JSON 是否存在”判断是否跳过评分，随后遍历目录中的全部 JSON 进行汇总。修改预测内容后，旧评分仍可能被复用；第二轮删除部分问题后，遗留 JSON 仍可能进入统计。AI 建议设计两轮连续执行的状态场景，并以输入内容而不是文件是否存在作为缓存有效性的判断条件。

**人工判断**

该问题会静默改变评估指标，属于有效缺陷。小组将其选为模块二主缺陷 D2-001，不重复使用模块一的三个缺陷。

## 2 测试用例生成

**人工输入**

> 基于上述风险和现有 pytest 风格，生成不少于 15 条单元测试。测试不能访问真实视频或外部 API，需要覆盖 JSONL 解析、异常评分、问题编号、缓存失效、本轮结果隔离和接口 Mock。每条用例应包含明确输入和单一断言目标。

**AI 输出摘要**

AI 按输入解析、评分边界、指标鲁棒性、文件路径、缓存状态和接口 Mock 六类提出候选测试。人工删除了与模块一重复的源码字符串检查，并保留 20 条可稳定自动化的用例，编号为 AI-201 至 AI-220。

## 3 缺陷定位与修复

**人工输入**

> AI-218 和 AI-219 分别要求预测变化后缓存失效、汇总时忽略其他轮次文件。请沿数据流定位根因，给出对现有结构影响最小的修复，并保留缓存以避免重复调用评分 API。

**AI 输出摘要**

AI 将根因定位为两个仅依赖文件状态的判断：跳过逻辑只检查文件名，汇总逻辑读取目录中的全部 JSON。修复增加了安全缓存文件名、缓存输入比对和按当前 `prediction_set` 汇总三个步骤。相同输入仍可命中缓存，预测答案或标准答案变化时重新评分，其他轮次文件不参与当前指标。

## 4 人工复核与反思

人工复核发现，AI 最初倾向对所有非法输入直接抛出异常，但模块一既有契约要求越界评分裁减到 0 至 5、非数字值按 0 处理。最终实现沿用已有契约，没有照搬 AI 的异常策略。小组还检查了生成测试是否依赖实现细节，保留行为断言，删除仅验证局部变量名称的建议。

完整回归执行结果为 53 条用例全部通过，其中模块一 33 条、模块二 20 条。测试使用临时文件和 Mock，不调用真实评分服务。
